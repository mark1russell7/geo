# Roadmap

This file is the plan of geo. The Status page of the site reads it, and the tracker of the project mirrors it.

| ID | Item | Status | Summary |
| --- | --- | --- | --- |
| R1 | The first package | done | @mark1russell7/geo 0.1.0 is on npm: points, distance, boxes, a point in a polygon, overlap, geohash and GeoJSON. |
| R11 | A limit on the longitudes of a polygon | done | A polygon with a longitude of 1e12 made `locatePoint` run for a very long time. The tests now refuse a longitude out of -540 to 540. Version 0.2.0. |
| R2 | The distance from a place to an area | done | `distanceToGeometryKm` gives the great-circle distance from a point to a polygon, a line or a point. The alert system needs it to match a place and its buffer against the polygon of an alert. Version 0.2.1. |
| R3 | The alert system matches places by shape | done 2026-11-15 | The core of the alert system matches a place and its buffer against the polygon or the circle of an alert, with this package. Part 1: the region codes are the floor, and a shape adds a place in its buffer. Part 2: the shape of a CAP area block decides for that block. |
| R4 | Exact moves across the antimeridian | done 2026-11-15 | `@mark1russell7/predicates` 0.1.3 has exact predicates on moved points (algebra A27, #176), and 0.1.4 has the exact ring test `locateInRings` (A28, #178). The strategist chose predicates as the home of the ring test. geo 0.3.1 moves the point with no rounding, imports the ring test and drops its copy. It keeps only the rule of holes of GeoJSON and the test of a point on an open line. The limit of 1e-12 degrees goes. Version 0.3.1 (#12). |
| R14 | Fast simplification of large states | done 2026-11-15 | `simplifyRegions` of 0.3.0 takes approximately 7.4 s for the 552 NWS regions of Texas (325,410 positions), and it blocks the event loop of an alert instance. The target of alerts is under 0.5 s on a CI runner. First a bench in CI with `rigor-bench` on seeded regions with shared edges, from 10^3 to 10^6 positions, and a CPU profile. Then the changes that the profile supports, with a speed gate. The prediction comes here before the code. Part 1: the package `packages/bench` and the workflow `bench-simplify.yml` measure geo 0.3.1, its noise and its profile. In CI, `tx-552-325k` takes 5.4 s. The exact edge distance of each scanned position takes 84 % of the time. Part 2 (the fix): an exact skip bound in the scan, fewer bisection steps, a lazy tree and number ids for the topology. The prediction (made before the code): the time of `tx-552-325k` goes from 5.4 s to 150 to 500 ms, and each case keeps the output of 0.3.1. The speed gate of the bench holds the budget and the growth. The result in 5 CI runs: `tx-552-325k` takes 205 to 275 ms, and geo 0.3.1 takes 3.7 to 4.6 s. Each case keeps the output. The limits of the gate come from these runs: 360 ms and a growth of 12. Version 0.3.2 (#16). |
| R12 | Simplify regions that share edges | done | `simplifyRegions` and `regionSimplifier` simplify the counties and zones of a state for the alert map. Neighbor regions keep one shared edge, so no gap and no overlap opens. The tolerance is in km for each zoom level. Version 0.3.0. |
| R13 | Uniform values in the property tests | done | `fc.double` with a range gives values near 0 in 93 % of the draws. Each ranged property now uses `uniformDouble` of `@mark1russell7/rigor-testkit`. |
| R6 | The live demo site | done 2026-11-15 | An interactive globe and flat map: pick or draw an area, move a place, and see the location, the distance, a buffer, the box and the geohash cells. The site check uses the demo at 360, 390 and 1280 pixels (#15). |
| R5 | `@procedures/geo` uses this package | in progress | `greatCircleKm` and the geohash of `@procedures/geo` become calls of this package. |
| R7 | Circles as polygons | done | `circleKm` and `circleMeters` give a circle on the Earth as a GeoJSON polygon for a map, for example the circle of a CAP alert or the buffer of a place. A circle across the antimeridian is cut there. A circle around a pole has an edge along the pole. A buffer of a line or a polygon is R15. Version 0.4.0. |
| R10 | Large polygons and many places | in progress | `locatePoint` examines each edge of the polygon for each place, and it checks the whole polygon again at each call. The target is a polygon with 100,000 vertices and 10,000 places. Part 1: the suite `locate` of `packages/bench` measures geo 0.3.1 in CI on coasts from 10^3 to 10^6 vertices, a star and a MultiPolygon of 552 parts. Part 2: the exact test of one edge against the ray of a point goes to `@mark1russell7/predicates`, the home of the ring test. Part 3: `pointLocator` checks the polygon one time and puts its edges in bands of latitude. Each place then examines only the edges of its band. The limits of its speed gate come from 5 CI runs. The prediction comes before the code. |
| R8 | The distance between two areas | later | The great-circle distance between two geometries. |
| R9 | Geodesics on the WGS84 ellipsoid | later | The distance, the bearing and the destination on the ellipsoid, with the method of Karney. |
| R15 | Buffers of lines and polygons | later | The area within a distance of a line or a polygon, as a GeoJSON polygon for a map. `distanceToGeometryKm` already tests a place against such a buffer. |
